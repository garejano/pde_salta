# EFC-6492 — Aumentar limite do tamanho do documento de laudo

> **Status local:** ⛔ **Descartado** — decisão do usuário em 2026-08-18, não será implementado. Card segue em Backlog no Jira; esta anotação é só para o contexto local.

---

## 1. Contexto e Motivação

O sistema permite o registro de laudos de alunos com Necessidades Educacionais Especiais (NEE). O limite atual de upload impede o envio de laudos com muitas páginas e imagens embutidas — documentos comuns em avaliações clínicas e especializadas. A restrição existe tanto no serviço quanto na infraestrutura, que suporta no máximo 10 MB por requisição síncrona, tornando inviável simplesmente aumentar o valor configurado.

**User Story:** Como usuário responsável pelo cadastro de NEE de alunos, quero fazer o upload de laudos com até 30 MB, para que documentos extensos com imagens embutidas possam ser registrados sem rejeição.

---

## 2. Critérios de Aceitação

- **CA-01:** O sistema deve aceitar o upload de laudos com tamanho de até 30 MB.
- **CA-02:** Quando o arquivo enviado exceder 30 MB, o sistema deve informar o limite máximo aceito de forma clara.
- **CA-03:** O upload deve ser concluído com sucesso para laudos com múltiplas páginas e imagens embutidas, sem truncamento ou corrupção do conteúdo.
- **CA-04:** Após o upload bem-sucedido, o laudo fica disponível para consulta no registro do aluno.
- **CA-05:** O limite de 30 MB deve ser configurável sem necessidade de alteração de código.

---

## 3. Subtarefas

Nenhuma subtarefa.

---

## 4. O Que Precisa Ser Feito

- O API Gateway tem limite de 10 MB para payloads síncronos; para suportar 30 MB, o upload deve ser feito diretamente para o S3 via URL pré-assinada (pre-signed URL), sem trafegar pelo API Gateway.
- O `S3FileUploadService` já existe no repositório mas não está sendo utilizado para o fluxo de laudos — avaliar reuso nessa implementação.
- O limite de tamanho deve ser externalizado para configuração (`appsettings`), não hardcoded no serviço.
- Esta story é uma continuação/evolução da EFC-6380 (já concluída), que tratou o hardcode de 10MB mas não migrou para upload direto S3.
