# EFC-6381 — Melhorias na Tipação de transtorno

## 1. Contexto e Motivação

Dois campos do formulário NEE precisam de evolução:

1. **Campo "possui laudo":** Atualmente lista suspensa com "sim" e "não". O usuário quer adicionar a opção "em avaliação", totalizando 3 opções.
2. **Campo "tipo de transtorno":** Atualmente é um campo de texto livre. A solicitação é transformá-lo em lista suspensa com a lista curada pela equipe pedagógica — **não baseada em CID**. Alguns itens possuem subitens obrigatórios: ao selecionar TEA ou TEAp, o usuário deve escolher o nível/subtipo específico.

**Achado importante:** o campo "possui laudo" não existe ainda — o campo `PossuiRelatorio` (bool) é diferente (refere-se a relatório pedagógico). O campo `tipoTranstorno` também não existe — hoje há apenas `Diagnostico` (string livre). Os campos novos precisarão ser criados do zero.

Repositório: `notas` — funcionalidade `NecessidadesEducacionaisEspeciais`.

---

## 2. Critérios de Aceitação

- **CA-01:** O campo "possui laudo" deve ter 3 opções: sim, não, em avaliação.
- **CA-02:** O campo "tipo de transtorno" deve ser uma lista suspensa com os itens da tabela abaixo.
- **CA-03:** Para TEA e TEAp, um segundo select deve aparecer com os subitens — a seleção do subitem é obrigatória.
- **CA-04:** O item "OUTROS" exibe campo de texto livre para descrever a necessidade.
- **CA-05:** Consultas e exportações funcionam corretamente tanto para registros com texto livre legado (campo `Diagnostico`) quanto para novos registros.

## 4. O Que Precisa Ser Feito

**Pré-requisito:** scripts SQL da Fase 1 do EFC-6379 aplicados.

**Lista de transtornos (curada pela equipe pedagógica):**

| Sigla | Descrição | Subitens |
|-------|-----------|----------|
| TEA | Transtorno do Espectro Autista | TEA Nível 1, TEA Nível 2, TEA Nível 3 |
| AH/SD | Altas Habilidades/Superdotação | — |
| TDAH | Transtorno do Déficit de Atenção com Hiperatividade | — |
| TEAp | Transtorno Específico da Aprendizagem | Dislexia, Discalculia, Disgrafia, Disortografia |
| TAG | Transtorno de Ansiedade Generalizada | — |
| TOD | Transtorno Opositor Desafiador | — |
| DI | Deficiência Intelectual | — |
| DF | Deficiência Física | — |
| DA | Deficiência Auditiva | — |
| DV | Deficiência Visual | — |
| DMu | Deficiência Múltipla | — |
| TDL | Transtorno do Desenvolvimento da Linguagem | — |
| TPAC | Transtorno do Processamento Auditivo Central | — |
| OUTROS | Outros | — |

Quando o item selecionado tem subitens (TEA, TEAp), o usuário **deve** escolher o subitem — o pai não pode ser salvo diretamente. O ID salvo em `AlunoNecessidadesEspeciais.TipoTranstorno` é sempre o item mais específico (subitem ou pai sem filhos).

**Backend — TipoTranstorno:**
- Criar `TipoTranstorno.cs` — campos: `Codigo`, `Descricao`, `ParentId` (int? nullable, self-referencing FK), `Ordem` (int).
- Criar mapping com self-referencing FK (`HasOptional(Parent).WithMany(Subitens)`).
- Endpoint `GET /tipo-transtorno` retorna **apenas itens raiz** com `Subitens` preenchidos, ordenados por `Ordem`.

**Backend — NEE:**
- Modificar `AlunoNecessidadesEspeciaisGetResponse.cs` — adicionar `PossuiLaudoStatus` (int?), `TipoTranstorno` (nested DTO com `Id`, `Codigo`, `Descricao`, `ParentId`), `TipoTranstornoOutro` (string?).
- Modificar `AlunoNecessidadesEspeciaisSaveRequest.cs` — adicionar `PossuiLaudoStatus`, `TipoTranstornoId`, `TipoTranstornoOutro`.
- Modificar `NEEGetNecessidadesService.cs` e `AlunoNecessidadesEspeciaisRepository.cs` — eager load `TipoTranstorno` (incluindo `Parent` para reconstruir a seleção no frontend).

**Frontend:**
- Modificar `aluno-nee.model.ts` — adicionar `PossuiLaudoStatus` (enum: 0=Nao, 1=Sim, 2=EmAvaliacao) e interface `TipoTranstornoResponse` com `subitens`.
- Criar `tipo-transtorno.service.ts` — GET lista de raiz com subitens.
- Modificar `edicao-nee.component.ts` — lógica de dois selects: ao selecionar item com subitens, exibir segundo select obrigatório; `TipoTranstornoId` salvo é sempre o id do subitem (ou do pai se sem subitens).
- Campo de texto livre `TipoTranstornoOutro` exibido apenas quando `Codigo === 'OUTROS'`.
- Retrocompatibilidade: exibir `Diagnostico` (legado) como somente-leitura se `TipoTranstornoId = null`.
- Ao carregar edição com subitem salvo: pré-selecionar o pai no primeiro select e o subitem no segundo.
