# Plano Técnico — EFC-6665

> Gerado em: 2026-07-31

## Contexto

`documentacao-pedagogica` hoje sincroniza o percentual de frequência do aluno consultando o módulo legado de frequência via HTTP. Como o cálculo migrou para `estrutura-pedagogica` (tabela `AlunoPercentualFrequencia`), é necessário expor esse dado por um novo endpoint que replique fielmente o contrato legado (`GET api/aluno/percentualfrequencia-aluno?hashUsuarioOrigem={guid}`, resposta `ServiceResult<List<PercentualFrequenciaResponse>>`), e então redirecionar `documentacao-pedagogica` para consumir esse novo endpoint, sem alterar seu processamento local (`SyncPercentualFrequenciaService`).

## Convenções aplicáveis

**estrutura-pedagogica:**
- Camadas: API (Controllers, sem lógica) → Domain.Services → Domain (entidades/interfaces) → Infra (repositórios EF Core). DI por autodiscovery via reflection.
- DTOs referenciam entidades relacionadas por `Hash` (Guid), nunca `Id`.
- Consultas de leitura usam `QueryableAtivos()` e projeção via `.Select()` — sem `.Include()`.
- Novo service segue `.claude/commands/criar-service.md`: interface herda `IBaseService`, primary constructor, `ValidarRequest`, retorno sempre em `ServiceResult<T>`.
- Testes de integração seguem `.claude/commands/criar-testes.md`: repositórios reais (`AddTransient`), outros services e `UsuarioAutenticadoRepository` mockados.
- Endpoints normalmente exigem `[RequiredAuthorization]`; `[AllowAnonymous]` é exceção rara e deve vir comentada.
- Parâmetros de filtro normalmente vão no corpo da requisição — este card exige uma **exceção deliberada** para replicar a querystring do contrato legado.

**documentacao-pedagogica:**
- Chamadas a sistemas externos passam por `ApiRepository`, com `baseUrl`/`apiKey` vindos de uma seção dedicada em `SettingsGetter.Instance`.

## Critérios de Aceite

- CA-01: Retornar um percentual para cada combinação de ano letivo e série com frequência calculada.
- CA-02: Identificar o aluno pelo mesmo identificador de origem (hash) já usado na integração.
- CA-03: Cada percentual deve indicar inequivocamente o ano letivo e série de origem.
- CA-04: Percentual deve refletir o valor mais atualizado calculado em estrutura-pedagogica.
- CA-05: `documentacao-pedagogica` não deve precisar mudar seu processamento — só a origem da consulta muda.
- CA-06: Aluno sem percentual calculado → lista vazia, sem erro.
- CA-07: Identificador inexistente/inválido não deve quebrar a sincronização.

## Restrições e riscos

- **Formato do percentual como string**: `Percentual` é `decimal` em estrutura-pedagogica; a conversão para string deve preservar formatação compatível com o que `SyncPercentualFrequenciaService` espera (grava direto em `HistoricoSerie.PercentualFrequencia`, sem parsing adicional). Validar formato (casas decimais, separador) durante a Fase 8.
- **Config compartilhada em documentacao-pedagogica**: `Project.Frequencia` é usada também por `FrequenciaRepository` (`api/diariodeclasse/chamadas`, fora de escopo) — a Fase 6 cria seção nova e não deve tocar na existente.
- **Limitação pré-existente em `SyncPercentualFrequenciaService`**: o matching hoje usa só `HashOrigemAnoLetivo`, ignorando `HashOrigemSerie` — comportamento existente, fora de escopo (CA-05 exige não alterar o processamento), mas documentado aqui para não ser confundido com bug introduzido por esta mudança.
- **Primeiro uso de autenticação por API-Key em estrutura-pedagogica** (Fase 4): não há precedente no repositório: revisar com atenção antes de aprovar para produção.
- **Dados de aluno/PII**: testes de integração devem usar fixtures sintéticas, nunca dados reais.
