## Fase 1 — Codec de valor por tipo (base das Fases 2 e 3; resolve o Ponto 3 da análise)

**Objetivo:** um único lugar que sabe, para cada `tipoResposta`, como ir e voltar entre o formato
que o WIDGET usa (`control.value`) e o formato que a `PerguntaAnamneseResponse`/
`RespostaAnamneseRequest` usam — em vez de espalhar essa conversão em dois lugares (GET e SAVE)
divergindo com o tempo.

**Novo arquivo:** `anamnese-valor-codec.ts` (mesma pasta do mapper).

```ts
interface CodecValor {
  /** PerguntaReal (ou InstanciaCampoReal, no caso de cadeia) → valor que o control do widget espera. */
  daResposta(fonte: RespostaEscalarReal): unknown;
  /** valor atual do control → campos de RespostaAnamneseRequest (só os relevantes a esse tipo). */
  paraResposta(valor: unknown): Partial<RespostaAnamneseRequest>;
}

// RespostaEscalarReal = os 7 campos de resposta que tanto PerguntaReal quanto
// InstanciaCampoAnamneseResponse têm em comum (respostaBit, respostaTexto, respostaNumerica,
// respostaDataHora, hashesOpcoesSelecionadas, hashesDisciplinasSelecionadas,
// hashAlunoEscolaMesmoResponsavel) — extrair como interface própria pra reuso entre pergunta
// "normal" e instância de cadeia repetível.

const CODECS_POR_TIPO: Record<number, CodecValor> = { /* uma entrada por tipoResposta, espelhando RESOLVEDORES_POR_TIPO */ };
```

**Pontos de atenção por tipo (confirmados na análise anterior):**
- `SimNao`: `daResposta` → `respostaBit === true ? 'sim' : respostaBit === false ? 'nao' : null`; `paraResposta` → inverso (`'sim'→true / 'nao'→false / null`).
- `Sexo`: **hoje `OPCOES_SEXO` usa hash string `'1'/'2'`** — `daResposta` → `respostaNumerica != null ? String(respostaNumerica) : null`; `paraResposta` → `{ respostaNumerica: valor != null ? Number(valor) : null }`.
- `ListaOpcoes` única (radio ou dropdown): valor do widget é **escalar** — `daResposta` → `hashesOpcoesSelecionadas[0] ?? null`; `paraResposta` → `{ hashesOpcoesSelecionadas: valor ? [valor] : [] }`.
- `ListaOpcoes` múltipla (checkbox/multi-select): já é array dos dois lados — `daResposta`/`paraResposta` são passagem direta (`[...hashesOpcoesSelecionadas]` / `{ hashesOpcoesSelecionadas: valor }`).
- `TextoAberto` / `Telefone` / `Celular`: usam `respostaTexto` — passagem direta.
- **`Inteiro` é DIFERENTE dos outros 3 "texto simples"** — mesmo widget (`text-field`), mas o campo de resposta é `respostaNumerica`, não `respostaTexto` (confirmado em `anamnese-tab.component.html:78-83` de produção). Precisa de codec próprio, mesmo compartilhando `RESOLVEDORES_POR_TIPO` (widget) com os outros três.
- `Data`: `respostaDataHora` (ISO) ↔ `yyyy-MM-dd` — igual ao `toDateInputValue` de produção.
- `DisciplinasAluno`: usa `hashesDisciplinasSelecionadas`, campo SEPARADO de `hashesOpcoesSelecionadas` — não pode reaproveitar o codec de ListaOpcoes múltipla apesar do widget (`MultiSelectFieldComponent`) ser o mesmo.
- `AlunoComMesmoResponsavel`: sem codec real ainda (Ponto 5, pendente) — `daResposta`/`paraResposta` viram no-op (`null`/`{}`) enquanto o widget for o fallback de texto.

## Fase 2 — `valorInicial` no GET (Ponto 1)

**Objetivo:** `mapearPerguntaSimples`/`mapearCadeiaRepetivel` passam a preencher
`FieldConfig.valorInicial` usando os codecs da Fase 1, para um aluno que já respondeu aparecer com
o formulário pré-preenchido.

- `mapearPerguntaSimples`: depois de resolver o widget via `RESOLVEDORES_POR_TIPO`, chamar
  `CODECS_POR_TIPO[pergunta.tipoResposta]?.daResposta(pergunta)` e setar em `valorInicial`.
- `mapearCadeiaRepetivel`: hoje só monta `subItens` (a ESTRUTURA da cadeia, sem valor). Precisa
  passar a montar também o VALOR inicial do campo `control` do `RepeatableGroupFieldComponent` —
  que é `Record<FieldConfig.id, unknown>[]` (um objeto por instância, chave = id do sub-item).
  Fonte: `pergunta.instancias[k]` de CADA pergunta da cadeia (mesmo índice `k` em todas, contrato
  já usado por produção em `criarControleRepetivel`). Como hoje `mapearCadeiaRepetivel` retorna só
  o `FieldConfig` (sem o valor do control, que é setado por fora, no `FormSectionBuilderComponent`
  a partir de `campo.valorInicial`) — este ponto precisa que o `FieldConfig` da RAIZ da cadeia
  também carregue `valorInicial: InstanciaRepetivel[]` (usando os codecs por sub-item).
- **Teste manual:** só dá pra validar visualmente com um dataset de aluno COM respostas — os dois
  datasets atuais (`data.json`/`data_infantil.json`) são de alunos sem respostas. Vale pedir um
  terceiro dataset (aluno já respondido) antes de considerar esta fase concluída, ou simular
  localmente preenchendo `respostaBit`/`hashesOpcoesSelecionadas`/etc. à mão numa cópia do JSON
  pra teste.

## Fase 3 — Conversão para salvamento (Ponto 2)

**Objetivo:** função que lê o `FormGroup` (valor bruto que `form-section-builder` já expõe hoje via
`formularioCriado`) e devolve um array no formato `RespostaAnamneseRequest[]`, pronto pra (no
futuro) virar o `respostas` de `SalvarAnamneseRequest`.

**Novo arquivo:** `anamnese-salvar-mapper.ts` (mesma pasta).

```ts
interface RespostaAnamneseRequest {
  hashPergunta: string;
  respostaBit: boolean | null;
  respostaTexto: string | null;
  respostaNumerica: number | null;
  respostaDataHora: string | null;
  hashesOpcoesSelecionadas: string[];
  hashesDisciplinasSelecionadas: string[];
  hashAlunoEscolaMesmoResponsavel: string | null;
  instanciaIndice: number | null;
}

export function montarRespostasParaSalvar(
  dados: AnamneseRealResponse,
  valorDoFormulario: Record<string, unknown>,
  camposVisiveis: Set<string>,             // ver Fase 4 — só entra o que está visível
): RespostaAnamneseRequest[]
```

**Regras a replicar (de `AnamneseTabComponent.salvar()`/`paraRespostaRequest()`/`desmontarInstancias()`):**
- Pergunta sub-item de cadeia (`hashPerguntaAgrupadora` preenchido) nunca entra solta — só via a
  raiz.
- Pergunta condicional não visível no momento do salvar não entra (depende da Fase 4).
- Pergunta repetível: ler o array de instâncias do `valorDoFormulario[raiz.id]`, gerar uma entrada
  por (instância × pergunta da cadeia) com `instanciaIndice = índice da instância`, e **descartar
  instâncias inteiramente vazias** (mesmo critério de `instanciaEstaVazia`: todos os codecs daquela
  instância devolvem valor "vazio").
- Usar os `paraResposta()` da Fase 1 pra cada campo escalar.

**Fora desta fase (não faz parte do "mapper"):** a chamada HTTP em si
(`PainelAlunoService.salvarAnamnese`) — ver Fase 5. Esta fase entrega só a função pura de
conversão; pode ser exercitada na tela de exemplos mostrando o resultado dela ao lado do "ver valor
do formulário" cru, pra comparar visualmente (dado bruto do control → payload convertido).

## Fase 4 — Visibilidade condicional (Ponto 4) — **muda o motor genérico, não só o mapper**

Esta é a única fase que sai da pasta da demo e mexe em `shared/form-section-builder/` — o motor
hoje não tem NENHUM conceito de campo condicional (`form-section-builder.component.html` renderiza
todo `campo` de `grupo.itens` sem `*ngIf`). Avaliar com cuidado antes de implementar, já que
qualquer outro consumidor futuro do motor herda essa mudança.

**Modelo escolhido:** declarativo, não uma função arbitrária — `FieldConfig` ganha um campo novo:

```ts
// form-section-builder.models.ts
export interface FieldConfig<TProps = Record<string, unknown>> {
  // ...campos existentes...
  /** Visível só quando esta opção (hash) está selecionada em QUALQUER outro campo do formulário —
   * mesmo critério de perguntaVisivel() da Anamnese real (não é "campo X = campo Y", é "essa opção
   * está selecionada em algum lugar"). Sem isso, o campo é sempre visível. */
  visivelSeOpcaoSelecionada?: string;
}
```

**No `FormSectionBuilderComponent`:**
- Computar, a cada `formGroup.valueChanges` (com `debounceTime(0)` ou similar pra não recalcular a
  cada tecla em campos de texto — avaliar), um `Set<string>` com TODAS as opções atualmente
  selecionadas em TODOS os controles cujo valor seja array de hashes OU hash escalar (normalizar
  igual a `hashesSelecionadosDoControl` de produção).
- Expor `campoVisivel(campo: FieldConfig): boolean` pro template:
  `!campo.visivelSeOpcaoSelecionada || opcoesSelecionadasGlobalmente.has(campo.visivelSeOpcaoSelecionada)`.
- Gatear `<div class="form-section-builder__campo" *ngFor="...">` com
  `*ngIf="campoVisivel(campo)"`.
- **Limpeza ao esconder** (item explícito do card: "Tratar campos condicionais — exibição/limpeza
  ao desmarcar opção-gatilho"): quando um campo passa de visível → invisível, resetar o control
  correspondente (`formGroup.get(campo.id)?.reset(campo.valorInicial ?? null, { emitEvent: false })`),
  senão o valor escondido ainda entraria na Fase 3 (conversão pro salvamento).

**No mapper (`anamnese-form-mapper.ts`):** setar `visivelSeOpcaoSelecionada: pergunta.hashOpcaoGatilho`
quando `pergunta.condicional && pergunta.hashOpcaoGatilho`.

**Teste real disponível:** `data.json` já tem a pergunta "Especifique:" (grupo Família) condicional
a "Outros" de "O aluno mora com quem?" — dá pra validar assim que a Fase 4 estiver pronta, sem
precisar de dataset novo.
