# EFC-6380 — Melhoria no upload de Laudos

## 1. Contexto e Motivação

O módulo NEE permite registrar laudos de alunos via upload de arquivo. Laudos clínicos extensos (com muitas páginas) são rejeitados pelo sistema por exceder o limite de tamanho configurado, impedindo o registro completo das informações do aluno.

O serviço atual usa hardcode de 10 MB como limite, e o API Gateway também tem limite de 10 MB — mas pode haver desalinhamento entre os dois. O ajuste precisa externalizar o limite para configuração e avaliar se 10 MB é suficiente ou se é necessário migrar para upload direto para S3 / multipart upload.

---

## 2. Critérios de Aceitação

- **CA-01:** O sistema deve aceitar upload de laudos com tamanho superior ao limite atual, respeitando o novo limite definido após investigação técnica.
- **CA-02:** Quando o arquivo exceder o tamanho máximo, o sistema deve exibir mensagem de erro clara informando o limite máximo aceito.
- **CA-03:** O upload deve ser concluído com sucesso para laudos com múltiplas páginas, sem truncamento ou corrupção do conteúdo.
- **CA-04:** Após upload bem-sucedido, o laudo deve permanecer disponível para consulta no registro do aluno.

---

## 3. Subtarefas

Nenhuma subtarefa.

---

## 4. O Que Precisa Ser Feito

1. **Investigar** o limite atual configurado no serviço de upload do NEE e comparar com o limite do API Gateway.
2. **Decidir a abordagem:** aumentar o limite (externalizar para config) ou migrar para upload direto S3 / multipart para suportar arquivos maiores.
3. **Externalizar** o limite de tamanho para variável de configuração (remover hardcode de 10 MB).
4. **Ajustar** a mensagem de erro para informar o limite máximo de forma clara.
5. **Testar** com laudos de múltiplas páginas, validando que o arquivo é armazenado e recuperado corretamente.
