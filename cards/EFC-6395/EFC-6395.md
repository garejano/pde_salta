# EFC-6395 — Ao editar Escola Gerencial combo Escola é exibida vazia

> **Fonte:** Jira (`gruposalta.atlassian.net`) — somente leitura. Não edite campos sincronizados diretamente aqui.  
> **Status:** Em Desenvolvimento | **Tipo:** Bug | **Prioridade:** Medium | **Última sincronização:** 2026-06-03

---

## 1. Contexto e Motivação

Ao editar uma Escola Gerencial já cadastrada, **no primeiro acesso** a combo de Escola é exibida vazia e bloqueada. No **segundo acesso** (reabrindo o formulário de edição), a escola aparece corretamente na combo.

O card inclui vídeo em anexo demonstrando o comportamento.

---

## 2. Critérios de Aceitação

- Ao abrir o formulário de edição de uma Escola Gerencial já cadastrada, a combo de Escola deve exibir o valor correto **já no primeiro acesso**, sem necessidade de reabrir o formulário.
- A combo não deve aparecer bloqueada quando houver um valor selecionado.

---

## 3. Subtarefas

Nenhuma subtarefa.

---

## 4. Causa Raiz (investigada)

**Bug de timing no `MultiSelectComponent.ngOnChanges`.**

**Fluxo do primeiro acesso:**
1. `ListarEscolaGerencialComponent.editarEscola(escola)` → `EditarEscolaGerencialComponent.start(escola)`
2. `start()` chama `preencherFormulario()` → `patchValue({ escolas: [] })` (combo sem valor)
3. `start()` chama `getEscolas()` → dispara HTTP; enquanto isso `loading = true` → combo desabilitada
4. HTTP retorna → `this.escolas = result.data` → `getEscolasEdicao()` → `form.get('escolas').setValue(hashes)`
5. `setValue` dispara `valueChanges` → `MultiSelectComponent.syncSelectedItems(hashes)` executa
6. **Problema:** nesse momento `this.options` no `MultiSelectComponent` ainda é `[]` — o Angular *não rodou change detection* ainda para propagar o novo `this.escolas` para o `@Input() options`
7. `syncSelectedItems` não encontra nenhum hash nas options → `selectedItems = []` → combo vazia
8. Angular roda change detection, propaga as options — mas `ngOnChanges` não tratava `changes["options"]`, então nunca re-sincronizava

**Por que funciona no segundo acesso:**
`close()` não limpa `this.escolas` no `EditarEscolaGerencialComponent`. No segundo `start()`, o `MultiSelectComponent` já tem as options carregadas da primeira abertura → `syncSelectedItems` encontra os hashes → combo exibe corretamente.

## 5. Arquivos Modificados

| Arquivo | Mudança |
|---------|---------|
| `src/shared/components/multi-select/multi-select.component.ts` | `ngOnChanges` agora reage a `changes["options"]` chamando `syncSelectedItems` |

**Diff da correção** (`multi-select.component.ts:101`):
```ts
// ANTES
ngOnChanges(changes: SimpleChanges): void {
  if (changes["selectedItems"]) {
    this.updateSmartPlaceholder();
  }
}

// DEPOIS
ngOnChanges(changes: SimpleChanges): void {
  if (changes["options"]) {
    this.syncSelectedItems(this.control?.value);  // re-sincroniza ao receber options async
  }
  if (changes["selectedItems"]) {
    this.updateSmartPlaceholder();
  }
}
```
