# EFC-7017 — Criação de RA Impulso/Enem

## 1. Contexto e Motivação

Card operacional recorrente do fluxo de cadastro de RA (Registro de Aluno) para o programa Impulso/Enem. Escolas públicas parceiras têm alunos que não são da rede Salta e precisam de um RA cadastrado para usar a correção de redação (simulados ENEM/Impulso).

Planilha do ciclo: anexada diretamente no card — **`Turmas Impulso .xlsx`** (anexo Jira, ID `180269`), aba **ENEM4**. Diferente dos ciclos anteriores (EFC-6732/6750/6799), que recebiam link do Google Sheets, aqui o arquivo veio como attachment nativo do Jira — baixar via `getJiraIssue`/API de attachment antes de iniciar o Passo 1 do guide.

Descrição do card no Jira é mínima (só a imagem da planilha embutida + "Aba: ENEM4") — sem critérios de aceitação explícitos, consistente com os ciclos anteriores.

---

## 2. Critérios de Aceitação

Não especificado explicitamente no card. Pelo padrão do processo (ver `projetos/importador_impulso/manual/guide.md`), o ciclo é considerado concluído quando:

- RAs gerados e inseridos no banco de produção para todos os alunos da aba **ENEM4**.
- Lista final de confirmação (Escola | Aluno | RA | Turma) entregue.

## 4. O Que Precisa Ser Feito

Executar mais um ciclo do fluxo de importação manual de RA Impulso, seguindo `projetos/importador_impulso/manual/guide.md`:

1. Baixar o anexo `Turmas Impulso .xlsx` do card EFC-7017 (aba **ENEM4**) e salvar em `projetos/importador_impulso/manual/EFC-7017/`.
2. Rodar `manual/scripts/resolve_ids_ra_impulso.sql` (Query 1 + Query 2) em homolog e produção — exportar CSV de IDs e anotar o `proximo_ra` de cada ambiente.
3. Validar o CSV (nº de linhas = combinações escola/turma distintas da planilha).
4. Rodar `manual/scripts/gerar_ra_impulso.py` para gerar `ra_alunos_impulso.sql`.
5. Executar o SQL gerado no banco (produção é sempre manual — IA não tem acesso via MCP).
6. Gerar e entregar a lista final de confirmação.

**Atenção (regra crítica do guide):** sempre rodar a Query 2 (próximo RA) de novo nesse ciclo, mesmo que um `--ra-start` de ciclo anterior pareça válido — o gerador não detecta colisão de RA entre alunos com nomes diferentes.

**Atenção (aprendizado do EFC-6750/EFC-6799):** turmas/escolas novas por ciclo costumam exigir novas linhas em `resolve_ids_ra_impulso.sql`; conferir combinações não mapeadas contra o banco (Turma/EscolaSerie) antes de assumir que é erro de digitação na planilha. A linha de exemplo da planilha (ex.: "Seguir este modelo") não é pulada automaticamente pelo script — usar `--alunos-csv` consolidado quando precisar excluí-la.

**Ferramentas em evolução (ver `projetos/importador_impulso/cli-development.md`):** a Fase 1 do CLI orquestrador (validação de dados + relatório de pendências — `validacao.py`, `mapping_registry.py`, `pendencia_writer.py`, `resolver_pendencias.py`) já está implementada e foi validada de ponta a ponta no EFC-6732. A Fase 2 (orquestração completa `gerar_ra_impulso.py` → SQL final) ainda não foi feita — neste ciclo, avaliar se vale rodar a Fase 1 (validação/pendências) antes do fluxo manual de sempre, para pegar escola/turma sem mapeamento mais cedo.
